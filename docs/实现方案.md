# 智仓 · 库存管理后台 — 实现方案

> 版本：v1.0（待确认）　　日期：2026-11-01
> 交付形态：Windows 免安装目录（双击 exe 启动），客户机零环境依赖；PC 端 + 手机端两套独立前端。

---

## 1. 需求理解与方案结论

| 需求 | 本方案对应实现 |
| --- | --- |
| 登录 / 登出 | JWT 登录态，支持"记住账号"、退出登录、改密后旧会话失效 |
| 管理员 / 普通员工两种角色 | 内置 `admin`（超级管理员）、`staff`（普通员工）两种角色，可扩展更多角色 |
| 管理员管理用户 | 用户增删改查、启停、重置密码、给单个用户单独配置可见菜单 |
| 管理员配置侧边菜单可见范围 | 角色维度批量授权 + 用户维度个性化覆盖，两级生效 |
| 员工仅可出入库、进不了用户管理 | 菜单不可见 + 后端接口鉴权双重拦截，前端隐藏不等于安全 |
| 商品增删改查 | 商品列表、搜索、分页、新增、编辑、停用/删除 |
| 出入库自动改库存 | 入库 `+`、出库 `-`，同一事务内写库存与流水，禁止负库存 |
| 库存 < 5 预警 | 首页看板低库存卡片 + 商品列表红色标记，阈值可按商品配置（默认 5） |
| PC + H5 双端 | 两套独立前端工程：`frontend-pc`（Element Plus）、`frontend-h5`（Vant） |
| Flask + SQLite | Flask 3 + SQLAlchemy 2 + SQLite（WAL 模式），单文件数据库 |
| 打包 exe | PyInstaller 打包（默认目录模式，可选单文件），内置前端产物，双击即用、自动开浏览器 |

**一句话结论**：一套 Flask JSON API + 一个 SQLite 文件 + 两套各自为政的前端（PC 重表格、H5 重触控），最终由 Flask 托管前端静态资源并打成单个 exe。客户机器上不装 Python、不装数据库、不装 Node。

## 2. 总体架构

```
┌───────────────────────────── Windows 主机（客户电脑） ─────────────────────────────┐
│                                                                                   │
│   ┌──────────────┐        HTTP/JSON        ┌──────────────────────────────────┐   │
│   │  PC 浏览器    │ ──────────────────────▶ │  Flask 应用（PyInstaller 免安装 exe） │   │
│   │  /pc/        │ ◀────────────────────── │  waitress 多线程 WSGI            │   │
│   └──────────────┘                         │  ├─ /api/*   JSON 接口            │   │
│                                            │  ├─ /pc/*    PC 前端静态资源      │   │
│   ┌──────────────┐        HTTP/JSON        │  ├─ /m/*     H5 前端静态资源      │   │
│   │  手机浏览器   │ ──────────────────────▶ │  └─ /        入口页（按 UA 分流） │   │
│   │  /m/         │ ◀────────────────────── │                                  │   │
│   └──────────────┘                         └───────────────┬──────────────────┘   │
│                                                            │                      │
│                                                   ┌────────▼────────┐             │
│                                                   │ data/app.db     │             │
│                                                   │ SQLite（WAL）    │             │
│                                                   └─────────────────┘             │
└───────────────────────────────────────────────────────────────────────────────────┘
```

- 前台访问：`http://127.0.0.1:8000`（本机）/ `http://<局域网IP>:8000`（手机同 Wi-Fi 访问）。
- 入口页自动判断 UA：手机跳 `/m/`，电脑跳 `/pc/`，同时保留手动切换链接（方便投屏演示）。
- 前端构建产物在打包时嵌入 exe；用户数据（数据库、日志）落在 exe 同级 `data/` 目录，升级程序不丢数据。

## 3. 技术选型

| 层 | 选型 | 说明 |
| --- | --- | --- |
| Web 框架 | Flask 3.x | 轻量、蓝图拆分清晰、打包体积小 |
| ORM | SQLAlchemy 2.x | 事务控制明确，配合 SQLite `BEGIN IMMEDIATE` 防并发超卖 |
| 数据库 | SQLite 3（WAL） | 零安装，单文件备份；本场景并发 < 20，完全够用 |
| 鉴权 | PyJWT（HS256） | 无状态、双端通用；`token_version` 支持改密/停用即时失效 |
| 密码 | Werkzeug `pbkdf2:sha256` | Flask 自带，不引第三方 |
| WSGI | waitress | Windows 上稳定，替代 Flask 开发服务器 |
| 打包 | PyInstaller 6（目录模式为默认，保留单文件配置） | exe + `_internal` 交付，启动快、杀软误报少；单文件版可选 |
| PC 前端 | Vue 3 + Vite + Pinia + Vue Router + Element Plus + ECharts | 后台管理标准组合，表格/表单/图表齐全 |
| H5 前端 | Vue 3 + Vite + Pinia + Vue Router + Vant 4 | 移动端组件成熟，触控与安全区适配好 |
| 测试 | pytest + Flask test client | 覆盖权限拦截、库存扣减、超卖、低库存边界 |

> 两套前端**不共用一套响应式页面**：PC 端是"侧边栏 + 表格 + 抽屉表单"，H5 端是"底部导航 + 卡片列表 + 底部弹层"，各自按设备交互习惯设计，仅共用后端接口与设计变量（颜色、圆角、间距）。

## 4. 角色与权限模型

### 4.1 权限三层结构

```
用户 user ──N:1──▶ 角色 role ──N:N──▶ 权限 permission（功能点：product:create / user:reset ...）
   │                    │
   │                    └──N:N──▶ 菜单 menu（侧边栏条目，绑定一个权限码）
   └──N:N──▶ 菜单 menu（用户级例外：单独开/关某几个菜单）
```

- **权限（permission）**：控制"能不能做"，后端每个写接口都校验，前端按钮据此显隐。
- **菜单（menu）**：控制"看不看得见"，决定侧边栏渲染结果与路由守卫。
- **角色（role）**：权限与菜单的批量模板；**用户级菜单配置**用于个别员工的例外情况（比如临时让其看到"出入库记录"）。
- 管理员角色为超级角色：拥有全部权限、全部菜单，不受菜单配置限制，避免把自己锁死。

### 4.2 内置角色权限矩阵

| 功能点 | 管理员 admin | 普通员工 staff |
| --- | :---: | :---: |
| 工作台看板（含低库存预警） | ✅ | ✅ |
| 商品查看 | ✅ | ✅（只读） |
| 商品新增 / 编辑 / 删除 | ✅ | ❌ |
| 入库办理 | ✅ | ✅ |
| 出库办理 | ✅ | ✅ |
| 出入库记录查看 | ✅ | ✅ |
| 用户管理（增删改、启停、重置密码、菜单授权） | ✅ | ❌ |
| 角色权限管理 | ✅ | ❌ |
| 菜单管理 | ✅ | ❌ |

默认员工侧边栏：`工作台 / 商品管理 / 入库办理 / 出库办理 / 出入库记录 / 我的`。管理员可在"菜单管理 → 可见范围"里随时增减，改完员工下次刷新即生效。

### 4.3 鉴权规则（关键）

1. 所有 `/api/*`（除登录）必须带 `Authorization: Bearer <token>`，否则 401。
2. 后端装饰器 `@require_perm("user:view")` 在接口层校验权限；**不依赖前端隐藏菜单**。
3. 前端路由守卫：进入页面前比对 `me.menus`，无权限跳 403 页。
4. 账号被停用 / 改密 → `token_version` 自增，旧 token 立即失效（401 踢回登录页）。
5. 登录失败连续 5 次锁定 10 分钟，锁定信息落库，重启 exe 依然有效。

## 5. 功能模块与页面设计

### 5.1 模块关联总览

```
                 ┌────────────┐
                 │  登录/登出  │
                 └─────┬──────┘
                       │ 签发 token + 返回可访问菜单
        ┌──────────────┼───────────────────────────┐
        ▼              ▼                           ▼
 ┌────────────┐  ┌────────────┐            ┌──────────────┐
 │  工作台     │  │  商品管理   │            │  系统管理     │
 │ 统计/预警   │  │  CRUD      │            │ 用户/角色/菜单│
 └─────┬──────┘  └─────┬──────┘            └──────┬───────┘
       │ 读库存/流水     │ 被出入库引用                │ 决定"谁能看到哪些菜单"
       ▼               ▼                            │
 ┌────────────────────────────┐                     │
 │ 入库 / 出库 / 出入库记录     │◀────────────────────┘
 │ 事务：改库存 + 写流水        │   （权限不足 → 菜单不可见 + 接口 403）

```

核心闭环：**商品**是库存载体 → **出入库**是唯一改变库存的入口 → **流水**留痕 → **看板**汇总并预警 → **系统管理**控制谁能操作哪些环节。

## 6. 数据模型

### 6.1 表清单（9 张）

| 表 | 作用 | 关键字段 |
| --- | --- | --- |
| `users` | 用户 | id, username(唯一), password_hash, real_name, phone, role_id, status, token_version, failed_attempts, locked_until, last_login_at, must_change_password, menu_mode(继承/自定义), created_at |
| `roles` | 角色 | id, code(唯一), name, description, is_builtin |
| `permissions` | 功能点 | id, code(唯一), name, module, sort |
| `role_permissions` | 角色-权限 | role_id, permission_id（联合主键） |
| `menus` | 菜单 | id, parent_id, name, path, icon, sort_order, visible, permission_code, is_builtin |
| `role_menus` | 角色-菜单 | role_id, menu_id |
| `user_menus` | 用户-菜单（覆盖角色） | user_id, menu_id |
| `products` | 商品 | id, code(唯一), name, category, spec, unit, stock, safety_stock(默认5), cost_price, sale_price, status, remark, created_at, updated_at |
| `stock_records` | 出入库流水（只读） | id, order_no(唯一), product_id, product_name, product_code, type(IN/OUT), quantity, before_stock, after_stock, operator_id, operator_name, remark, created_at |

索引：`users.username`、`products.code`、`products.name`、`stock_records.product_id`、`stock_records.created_at`、`stock_records.type`。
时间统一东八区 `YYYY-MM-DD HH:MM:SS`，金额 `DECIMAL(10,2)`，数量为正整数。

### 6.2 库存一致性策略

- 开启 `journal_mode=WAL`、`foreign_keys=ON`、`busy_timeout=5000`。
- SQLAlchemy 连接事件强制 `BEGIN IMMEDIATE`，写事务串行化，从根上避免两人同时出库导致超卖。
- 出库使用条件更新：`UPDATE products SET stock = stock - :q WHERE id = :id AND stock >= :q`，`rowcount = 0` 即库存不足，整事务回滚。
- 流水记录 `before_stock / after_stock`，可对账；流水不允许编辑/删除（只读审计）。
- 有流水的商品禁止物理删除，只能"停用"（`status=0`），历史记录不悬空。

| GET/POST | `/api/roles` | role:view / role:manage | 角色列表、新增 |

| GET/POST | `/api/products` | product:view / product:create | 列表（搜索/分页/库存状态）、新增 |

## 8. 关键业务规则

1. **登录**：账号密码校验 → 状态检查 → 锁定检查 → 签发 12 小时 JWT → 记录最后登录时间/IP。
2. **入库**：数量必须为正整数 → 事务内读当前库存 → `stock + n` → 写流水（单号 `IN20261101-0001`）。
3. **出库**：数量必须为正整数且 `≤ 当前库存` → 条件更新扣减 → 写流水（`OUT20261101-0001`）；库存不足返回 409 并提示"当前仅剩 X 件"。
4. **低库存**：`stock < safety_stock`（默认 5）即预警；看板按缺口排序，商品列表显示红标；`stock = 5` 不预警（严格小于）。
5. **菜单可见性算法**：
   `effective = (用户级配置 ? user_menus : role_menus) ∩ 角色已授权限对应的菜单`，再补齐父级、剔除 `visible=0`；管理员直接取全量。
6. **删除保护**：不能删除自己、不能删除内置管理员、不能删除最后一个管理员；内置角色不可删；有流水的商品只能停用。
7. **密码规则**：8–20 位，至少含字母与数字；重置后 `must_change_password=1`，下次登录强制改密。
8. **首次启动**：自动建库建表、写入内置角色/权限/菜单/演示商品，管理员 `admin / Admin@123456` 首次登录强制改密。

## 9. UI 设计规范（大厂风格）

- **色彩**：主色 `#1677FF`，深色侧栏 `#0B1B33 → #13294B` 渐变，成功 `#52C41A`，警告 `#FAAD14`，危险 `#FF4D4F`，页面底色 `#F5F7FA`，卡片白 + 8px 圆角 + `0 1px 2px rgba(0,0,0,.04)` 轻阴影。

## 10. 打包与部署

### 10.1 目录约定

```
智仓管理后台/
├─ 智仓管理后台.exe          # 双击启动
├─ _internal/               # 运行库（不可删除）
├─ 使用说明.md
└─ data/
   ├─ app.db                # SQLite 数据库（备份就复制这个文件）
   └─ logs/app.log          # 运行日志，按天滚动
```

### 10.2 打包流程（开发者侧，一次性）

1. `pnpm build` 分别构建 PC 与 H5 → 产物复制到 `backend/static/pc`、`backend/static/m`。
2. PyInstaller 读取 `build/app_dir.spec`（目录模式，默认交付）或 `build/app.spec`（单文件模式），把两套静态资源打入包内。
3. 代码内用 `sys._MEIPASS` 定位只读资源，用 `sys.executable` 同级 `data/` 定位可写数据。
4. 启动逻辑：单实例锁 → 端口探测（8000 起，占用则 +1）→ 初始化数据库 → 启动 waitress → 自动打开浏览器 → 控制台/托盘无窗口运行。
5. 附带 `build_exe.bat`，双击完成"装依赖 → 构建前端 → 打包 exe"，方便后续改版重新出包。

> 交付决策：默认采用 **PyInstaller 目录模式**（exe + `_internal`）。相比单文件，目录模式启动更快、不在临时目录解压、杀软误报更少；单文件模式保留在 `build/app.spec`，需要时执行 `python -m PyInstaller build/app.spec` 即可生成。

### 10.3 客户侧使用

1. 双击 exe，浏览器自动打开 `http://127.0.0.1:8000`，用 `admin / Admin@123456` 登录并改密。
2. 手机连同一 Wi-Fi，访问启动日志/弹窗提示的 `http://192.168.x.x:8000`。
3. 首次运行若 Windows 防火墙弹窗，需勾选"专用网络"允许；文档附一条 `netsh advfirewall` 放行命令备用。
4. 备份 = 复制 `data/app.db`；换机 = 拷贝整个目录。

> 说明：手机访问依赖局域网，这是"无服务器"形态的固有限制。若客户要求公网访问，需要额外做内网穿透/云主机，不在本期范围。

## 13. 范围边界与假设

- 单机单库、局域网使用；不做多仓库、多门店、供应商/客户、采购单、盘点、退货（数据结构预留扩展位）。
- 菜单管理控制"已有页面"的显示/命名/图标/排序/权限码；新增全新业务页面仍需前端开发（组件注册表机制）。
- 商品不含图片上传（可二期加），不含导出 Excel（可二期加）。
- 浏览器要求：Chrome/Edge 90+、iOS Safari 14+、Android Chrome 90+。
- 默认参数（可改）：系统名"智仓"、端口 8000、低库存阈值 5、token 12 小时、默认账号 `admin/Admin@123456`、`staff/Staff@123456`。
- 单文件版在个别杀软下可能误报，默认目录模式已规避；如客户坚持单文件，需加白名单。

## 15. 编码前逻辑自查（2026-11-01）

按"模块 → 表 → 接口 → 权限 → 菜单"逐条走查，发现并已修正以下依赖问题，代码将按修正后的模型实现：

| # | 问题 | 风险 | 修正 |
| --- | --- | --- | --- |
| 1 | 用户级菜单无法区分"继承角色"与"自定义为空" | 清空勾选后会被当成继承，配置失效 | `users.menu_mode`（inherit / custom），custom 时以 `user_menus` 为准 |
| 2 | 删除用户/商品后，流水里的姓名、商品名悬空 | 历史记录出现空白 | 流水冗余 `operator_name`、`product_name`、`product_code` 快照，外键 `ON DELETE SET NULL` |
| 3 | 角色权限页与菜单管理页都能改"菜单可见" | 两套规则冲突 | 明确唯一数据源 `role_menus`；角色页用两个 Tab（功能权限 / 菜单权限），菜单管理页是同一份数据的反向视图，接口共用 |
| 4 | 菜单可见但页面无权限 → 点进去 403 | 管理员配置出"死菜单" | 菜单绑定 `permission_code`，授予菜单时自动补齐该页面权限 |
| 5 | 首次登录强制改密只在前端提示 | 可绕过前端直接调接口 | 后端 `must_change_password=1` 时，除 `me / password / logout` 外全部 403 |
| 6 | 停用账号、改密后旧 token 仍有效 | 安全漏洞 | `token_version` 写入 JWT，每次请求比对；停用/改密/重置均自增 |
| 7 | 双击 exe 启动多个实例、端口冲突 | 数据竞争、打不开页面 | 文件锁单实例 + `/api/health` 探测；已运行则直接打开浏览器；端口占用自动顺延 |
| 8 | 两人同时出库可能超卖 | 库存变负 | 出入库走独立 SQLite 连接 `BEGIN IMMEDIATE` + 条件更新 `WHERE stock >= ?`，双保险 |
| 9 | 删除链未定义（自己/最后一个管理员/有用户的角色/有子菜单/有流水的商品） | 系统被锁死或数据悬空 | 统一返回 409 并给出明确文案；商品改为"停用" |
| 10 | PC 与 H5 菜单来源不一致 | 手机端出现无权页面 | 两端都从 `/api/auth/me` 的菜单树渲染，H5 Tab 只是它的子集映射 |
| 11 | 菜单路径可随意填写 → 配置出打不开的页面 | 菜单管理产生死链 | 菜单路径从"已注册页面"下拉选择（组件注册表），不支持手填任意路径 |
| 12 | 前端只有源码、客户机没有 Node | 无法直接运行 | 仓库内提交两套前端构建产物，`python run.py` 即可跑；Node 仅开发/打包时需要 |

另确认运行环境：本机 Python 3.12.8、Node 24.21.0、pnpm 11.28.5 均可用；Trae 中按 README 执行 `pip install -r requirements.txt` + `python run.py` 即可查看，无需安装 Node。
